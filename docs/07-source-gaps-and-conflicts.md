# Source gaps, conflicts and deviations

Every item below was found by reading the uploaded n8n JSON, the CSV exports and the historical runtime rows. Nothing here was silently reconciled: each entry states what the source does, what the target does, and why.
Status values: **GAP** (cannot be proven from the upload → conservative safe result), **DEFECT** (the source behaviour is clearly unintended), **CONFLICT** (two artifacts disagree, or the migration brief disagrees with the source), **PLATFORM** (behaviour-preserving substitution forced by the target platform).

Where a source and the brief disagree, the source wins and the disagreement is reported here (and pinned by a test), never edited away.

## Corrected earlier claim

An earlier draft of this file listed a `synthetic_Only` vs `synthetic_only` casing conflict. Re-checking the table mapping in Workflow 90 (`"synthetic_Only":"={{$json.synthetic_only}}"`) shows the column name matches the export exactly; `synthetic_only` is only a field on the in-flight JSON item. It is **not** a conflict and has been removed. Likewise, the earlier "reset vs resume" conflict was a misreading: in Workflow 03 the *Reset Runtime Utility Results* node sits on the chat-entry path only, and the evidence-resume path (*Send Evidence Accepted Message → Get Existing Runtime Results*) bypasses it (`evaluateCase` resets, `resumeAssessment` does not).

## Behaviour-preserving differences caused by platform constraints

1. LLM provider: OpenAI → Claude Agent SDK (G-03); model chosen by `CLAUDE_MODEL`.
2. `sendAndWait` chat pauses → persisted conversation state (G-24). Behaviour per turn is unchanged.
3. n8n form pages → React pages + JSON API; upload link points at `APP_BASE_URL/upload` (G-24).
4. PDF extraction library (G-23).
5. Data tables → PostgreSQL (`runtime_*` tables with JSONB payloads + key columns, unique/CHECK constraints) and raw `source.*` import tables.
6. Sub-workflow calls → in-process function calls (the seven utilities are exposed to the agent as MCP tools through the governed toolbox).
7. Audit and ID timestamps are real and monotonic (G-15, G-16).

## Safe defaults in force

- Any behaviour that cannot be proven from the upload resolves to `MANUAL_REVIEW` (`UNRESOLVED_SOURCE_GAP` for a missing utility fixture row).
- A rule with `Rule_Status = TBD` can never produce an automated approval or rejection (`CTRL-001 TBD_POLICY`).
- An unavailable external lookup is `REGISTRY_UNAVAILABLE` → manual review, never an implicit failure.
